# 031：机关房间与多选编辑

固定入口仍是本工作区「启动实验版.command」，runtime/Godot 与 game/ 不变；不清理或迁移 THORNBOUND-QuickJS-Lab 存档。本次仅更新实验工作区；根目录网页与正式旧工坊保持原有玩法。

## 使用流程

进入创意工坊，选中一个至少18×12格的矩形房间。在右侧「房间挑战」选择「木头人机关房」或「数字地砖」，确认应用模板。模板清理内部墙、普通机关和装饰，保留拼接门和开关，重新放置出生点；操作可整体撤销。取消确认不会改地图。已有地图若不选择新模板，则旧「木头人」「数字快答」规则保持。

也可直接在「我的地图」选择新增内置「大型机关房 · 木头人＋数字地砖」，先试玩两间连续示例，再选编辑调整/拼接/另存并加入游玩列表。

木头人：绿灯可移动、0.6秒转身预警后红灯停止；红灯期间任何实际位移会出现0.2秒激光锁定，随后失败。四条火带从上往下覆盖房间，按固定节奏交替喷发，必须在火带间的空隙停留。抵达最右侧安全区后解锁出口开关。新Boss为内置imagegen生成的独立透明木偶守卫图，原始提示词与出处见game/art/challenges/PROVENANCE.json；本次未修改生成原图。

数字地砖：走进中央九宫格后准备0.8秒，出现简单加减题；默认3秒走到正确数字。其他地板坠落时必须停在安全格1.2秒，复原后继续；默认完成2题解锁出口。按1/2/3不能跳过地砖判定。题数/时限可在房间属性中调整。数字地砖区域不允许墙体或普通对象覆盖，载入/试玩/发布时校验，避免正确答案无法落脚。

所有试炼完成后仍需到出口按F；配对门保留物理拼接/回返规则，最终开关按现有规则确认胜利。R重置当前房间挑战、机关与计时，M/衣柜/失焦按现有暂停流程冻结；未进入的房间不提前消耗答题时间。

## 机关多选

选择工具中：普通点击单选；Shift点击追加或取消；⌘/Ctrl+A选择本房间全部普通机关。选中一个机关后，「选择本房间同类机关」可一次选中所有地刺或其他同类机关。跨房间切换不保留旧选择。

选中多个后右侧出现统一时间面板。填写需要统一的启动延迟、重复周期、生效时间，留空字段保留各自原值；点应用后一次撤销可还原整组。周期缩短时，生效时长按周期上限收敛。非法数值整组拒绝，不会只改其中几个。未选中机关不会改变；方向/距离/引信仍单独编辑。批量延迟设为相同值会同步启动；需要保留错峰节奏时只改周期或生效时间。

## 管理与状态

目标用户：用房间拼接制作动作解谜关卡的地图作者。核心流程：选模板 → 拼接/布置 → 多选调时 → 保存草稿 → 从第一关试玩 → 加入游玩列表 → 正式游戏。

模块：room_trial.gd拥有空间试炼规则/地砖/火带/激光，room_challenge.gd兼容旧挑战并分派新类型，map_model.gd校验与reshape保存类型，main.gd处理编辑意图与界面，map_library.gd提供示例。存档仍为schema2，新增challenge.type值，旧字段继续读取。老版本不识别新类型；回退前先将新地图另存，避免用旧版覆盖。

多选修改先在副本上验证所有机关，再一次写入模型/撤销栈；多人方案仅设计，不加入网络状态所有者。多人完整方案见MULTIPLAYER_PLAN.md。

交付状态：代码完成、专项与完整回归通过、实际Godot渲染截图已检查；用户手感/审美认可待试玩。实际联网、安卓真机、新房间自由旋转喷火朝向和难度自动检测未包含在本次范围。

证据：reports/031/tests.log（专项），regression.log（完整工坊回归），wood.png/math.png/multi.png（实际Godot渲染），DELIVERY.json与SOURCE.zip（清单与源码）。修改前核心文件备份在reports/031/before，原用户地图与装备目录不变。
