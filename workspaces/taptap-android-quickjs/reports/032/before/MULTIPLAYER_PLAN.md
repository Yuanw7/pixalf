# 多人玩法建议：分路夺宝，集合撤离

建议先做2–4人合作闯关，保留个人抢宝的竞争感。团队必须一起完成出口条件，个人只竞争贡献和额外小宝石；首版关闭友伤与队友身体推挤，避免红灯和窄桥上的恶意阻挡。

## 一局的完整流程

集合大厅 → 看分路地图 → 各自选路/临时结伴 → 过机关取得核心宝石 → 携宝石回汇合祭坛交付 → 最终门开启 → 全部存活在线成员集合2秒 → 撤离结算。

初版一张手工地图，10–15分钟/局，不随机生成。中央大厅连接三条可往返的支路：

|支路|主要玩法|核心目标|合作点|
|---|---|---|---|
|红色·木偶守卫|红灯停、火带间停留、绿灯穿越|红宝石|先过的人可打开返回捷径，提示火带节奏|
|蓝色·数字地砖|计算后站正确数字|蓝宝石|每个人都能看到完整题目；有效人数不足不生成多站位题|
|绿色·机关长廊|错峰地刺、锯轮、箭弩|绿宝石|侧路拉杆短时停机关，为持宝队友开安全窗口|

宝石交付后点亮大厅对应槽位。三种核心都齐才开最终撤离路；拿到一颗就能回大厅，不强迫队伍在同一机关反复等待。

## 抢宝与团队目标如何共存

- 三色核心是团队钥匙，每种唯一。拿到核心的玩家有贡献奖，交回大厅后核心不可再被取出；同一物体不会重复计分。
- 每条路线额外布置小宝石与计时奖励，先拿者获得个人贡献；小宝石不是开门必需，落后队友不影响开门。
- 默认队友不能攻击或直接偷别人的背包。所谓“抢”是抢先选择路线、抢先拾取、竞争额外宝藏；之后可单独增加娱乐争夺模式，勿混入首个合作模式。
- 结算以团队成功为主（例如80%共享奖励、20%有限个人贡献）。救援、交付核心和开捷径也计贡献，避免只跑最快路线的人获益。

## 携带、倒地与防卡关

每人至多携带1颗核心，拾取显示持有人和方向。核心不会因落入熔岩、掉出地图或断线永久丢失：掉落在该房间最近的安全检查点，地图显示位置。

玩家倒地先掉核心，可由同伴在安全点长按3秒救援；15秒后允许主动回大厅，扣本局个人分而非删除进度。红灯倒地者成为观战幽灵，不占地砖也不触发机关。已交付核心不因死亡回退。全队倒地从大厅检查点重试，保留已交付核心，未交付核心回各自安全点。

离线玩家不占集合名额，未交付宝石回安全点；重新连入从大厅出生。首版不做房主迁移：房主退出时结束本局并明确通知，已结算个人成果保存。网络断线不伪装成通关。

## 多人机关的具体判定

木头人只处罚违规移动的人，不能一人移动激光全队。所有人共享相同红绿灯与火带节奏，服务端判断移动；迟到的网络包按有效时间窗处理，不能仅用客户端动画帧推断违规。关卡预警需覆盖预计延迟，并在高延迟时提示网络状态。

数字地砖先保留所有人站同一正确数字的版本，队友不互相挤出安全格。合作变体放到后续：不同玩家获得不同题目/颜色目标，但任意时刻需要的同时站位人数不能超过当前存活人数。

喷火、地刺、锯轮共用房间时钟。首次有人进入才启动房间，所有玩家离开时按统一规则停表；不能因某个客户端打开地图暂停所有人。多人M只显示个人地图，真正暂停要全队表决，首版可不提供。

## 编辑器需要的扩展

现有房间挑战配置与机关多选可直接复用。多人再新增：2–4个出生点、宝石点（核心/小宝石、唯一ID、颜色）、交付祭坛、安全掉落点、汇合区（需要核心颜色、半径、集合人数规则）和机关拉杆。地图校验要确认每色核心可从大厅到达且能返回、没有必须超出实际人数的同时开关。

房间模板是房间级规则；单机关是对象级配置。两者都由服务端统一写状态，客户端只发送移动、交互、拾取意图，不能自行增加宝石或宣布通关。

## 技术路线与分阶段验收

1. 本机多人状态模拟：四个玩家分路，核心抢取同帧只允许一个成功；掉落/交付/倒地/断线/重复请求不能复制宝石。此阶段先验证规则，不宣称联网。
2. 2人局域网原型：Godot ENet/房主权威，移动预测与服务端校正；统一机关时间，个人地图不暂停世界。验收两台机器一人一条支路、回大厅交付、开门集合完整通过。
3. 4人局域网：模拟延迟、丢包、重连，验证核心安全回收、红灯误伤率与软锁；按实际测试再定容忍窗口。
4. 再决定互联网方案：房间码/中继/专用服务器、安卓后台与重连。不能把局域网能连等同于公网可用，也不先花时间做排名、交易或房主迁移。

推荐先验收一张“大厅＋三支路＋撤离厅”的合作地图，再扩展随机房间与对抗玩法。当前文档为玩法/实现方案；本次没有增加实际联网功能。
